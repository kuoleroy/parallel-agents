## CI 抓出来的三个 bug（都是本机测不出来的）

机制测试只在作者一台 Windows 机器上跑过就发了版。0.2.0 首推，GitHub Actions 三条运行全红——两个真问题；修完再推，同一个 bug 又红了第二轮（见二）。shellcheck 那条 job 另报出一个冻结判定的静默失真（见三）。

### 一、脚本在 git 里没有可执行位

```
$ git ls-files -s scripts
100644 ... scripts/gate.sh
100644 ... scripts/new-task.sh
```

Windows 上跑 `bash tests/run-test.sh` 一切正常——Git Bash 把所有文件都当可执行。Linux 上，测试内部直接 `"$ROOT/scripts/new-task.sh"` 调用就是 `Permission denied`。真实用户的体验更糟：`./scripts/new-task.sh 01 data src/db` 在 macOS / Linux 上根本跑不起来。

已 `git update-index --chmod=+x` 修正，并加了第 10 条断言常驻盯这个位。

### 二、闸门会借用端口上别人的服务做实测

原来那段逻辑是「端口已经有人监听 → WARN 一句 → 直接拿它实测」。ubuntu 上进程回收比 Git Bash 严格，上一轮遗留的 node 还占着端口，于是闸门**给一个根本没跑本分支代码的进程出了结论**：合规分支被判 `FAIL 边界用例期望 4xx，实际 200`。

在 Windows 上这个 bug 是隐身的——遗留进程被更早回收，端口总是干净的，实测永远测对的东西。**换句话说：它不是让 CI 变红而已，它是会让闸门在真实项目里把"通过"发给错误的构建。**

现在改成：端口被占即失败，不猜、不借。

```
-- 接口实测
  FAIL  端口 21234 上已有服务，闸门无法确认它跑的是本分支代码。停掉它再跑；确实要测外部服务就显式设 HEALTH_URL
```

同时闸门起的服务在实测结束那一刻就收，并轮询确认端口真的释放了（`OK 测试服务已停，端口 21234 已释放`），不再拖到脚本退出。确实要测外部服务，用 `HEALTH_URL` 显式声明，闸门会 WARN 一句"无法确认来源"——把责任交回给人，而不是自己假装知道。

**第一版修法没修干净**：加上「端口被占即失败」之后，CI 又红了一轮——这次红的理由是 `FAIL 端口 N 上已有服务`，即上一轮闸门自己起的那个服务还是没散场。原因是 `kill $SERVE_PID` 打的是最外层子 shell，`SERVE_CMD` 外面套着 `sh -c`，真正监听的可能是孙进程；Windows 上整棵树跟着收，Linux 上不会。现在收服时按 `/proc` 沿子进程树 `TERM`，端口不释放再补一轮 `KILL`，两轮之后还占着就**如实报 FAIL 并把残留 pid 打出来**——宁可红得难看，也不给下一个任务留一个会被误当成本分支结论的端口。

### 三、冻结清单里的通配会被当前目录吃掉

`new-task.sh` 原来是这么把冻结清单传进检查的：

```bash
p_file_in_patterns "$f" $(cat "$FROZEN" | grep -v '^#' | ...)   # 没引号
```

不引号的命令替换会先做通配展开。清单默认项都是具体路径，所以一直没出事；只要用户往里加一条 `*.lock` 或 `*.env`，shell 就先去**当前目录**匹配它，传给冻结检查的变成碰巧存在的那些文件名，模式本身消失了。冻结判定于是静默失真——该拦的建任务请求照过，而且没有任何输出提示你它已经不看这条规则了。

这条是 shellcheck 的 `SC2046` 报的。它从未在作者机器上跑过（本机装不上 shellcheck，网络也装不了），所以那条 job 先标了 `continue-on-error`，只报告不阻断——**但它报的东西是真的**。改成逐行读进数组再传参。

顺带另一条 `SC2053`（`[[ "$f" == $p ]]` 右边没引号）是误报：这里要的就是通配匹配，加引号反而让它变成字面量比较，所以补注释抑制而不是改代码。

## 实录一：契约未实现，被接口实测抓住

分支只加了一句注释，边界、构建、体检全绿——契约要求的 400 没实现，靠 `curl` 当场抓住：

```
闸门: feature/search

-- 前置
  OK    基线 main
  OK    归属表已登记: 02 search · 端口 21234
-- 改动 1 个文件

-- 体检
  OK    worktree 干净
  OK    无验证残留

-- 边界检查（独占清单之外必须零改动）
  OK    零越界 · 零侵入 · 零动冻结

-- 任务书「不要动」复核
  OK    保护区零改动 (13 条)

-- 构建
    node --check server.mjs (在 .../wk-search)
  OK    构建通过

-- 接口实测
  OK    服务已启动 (pid 1557, port 21234)
  OK    健康检查 http://127.0.0.1:21234/api/health
  FAIL  边界用例期望 4xx，实际 200

闸门结果: OK 9 · SKIP 0 · FAIL 1
```

这就是「两个 agent 对同一个字段/同一条契约理解不同」那一类返工：它不是合并冲突，git 看不见，只有按契约跑一次真实请求才暴露。

同一分支按契约补上校验后：

```

    node src/api/__tests__/search.test.js (在 .../wk-search)

  OK    测试通过
    改既有 1 个 · 新增 0 个
      ~ src/api/search.js
  WARN  上面这些是既有文件，人工确认调用方与行为未被改动打穿

-- 人工清单（闸门不代答）
      [ ] 安全：硬编码密钥 / 未校验入参 / 越权 / 拼串 SQL / 日志里 PII
```

## 实录四：端口上站着别人的服务，闸门拒绝借用

在合规分支跑绿之后，测试自己往该任务的端口上起了一个**外来**服务，再跑一次闸门：

```
-- 接口实测
  FAIL  端口 21234 上已有服务，闸门无法确认它跑的是本分支代码。停掉它再跑；确实要测外部服务就显式设 HEALTH_URL

闸门结果: OK 7 · SKIP 0 · FAIL 1
```

这条是 0.2.0 首跑 CI 时补上的。旧逻辑遇到端口被占会 WARN 一句然后直接借用，ubuntu 上就靠这个把合规分支误判成了失败——见上文「这套测试自己放过的两个 bug」。

## 局限（请连同结论一起读）

1. **这是机制验证，不是效果验证。** 它证明闸门确实拦得住这些注入，**不**证明"用了它你的三 agent 并行返工从 X 降到 Y"。后者需要真实多 agent 运行，本仓库目前**没有**这个数据，也不宣称有。
2. **被测栈是 60 行的 node 微服务**，不是真实项目。边界、冻结、实测三项机制与语言无关，但 `BUILD_CMD` / `SERVE_CMD` / `TEST_CMD` 需要你按自己的栈配置。
3. **重叠判定是启发式**：支持精确路径、裸目录、`dir/**`、`dir/*` 和单层 `*.ts`，不支持取反与花括号展开。相邻清单是否真冲突仍需人判断，所以方法论要求"清单宁可窄不可宽"。
4. **未在 Windows 原生 PowerShell 下测试**，脚本走 Git Bash；`mktemp` / `curl` / `awk` 是依赖项。
5. 端口在每次跑测时随机取（`20000+`），所以实录里的端口与你本机不同。
